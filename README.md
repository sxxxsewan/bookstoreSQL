# Bookstore Database – SQL Practice Project

Реляционная база данных интернет-магазина книг с демонстрацией продвинутых возможностей SQL и хороших практик проектирования

## Что реализовано

### 1. Структура базы данных (нормализация 3NF)
- 7 связанных таблиц: `authors`, `publishers`, `categories`, `books`, `customers`, `orders`, `orderitems`, `reviews`
- Правильные внешние ключи (хотя в дампе они не прописаны явно - в продакшн лучше добавить)
- Ограничения: CHECK на статусы, диапазон оценок (1–5), NOT NULL где нужно

### 2. Триггеры (автоматизация бизнес-логики)
- `trg_update_book_status` - автоматически меняет статус книги на `out_of_stock` при нулевом остатке
- `trg_check_stock_before_insert` - проверяет наличие товара перед добавлением в заказ (блокирует, если недостаточно)
- `trg_update_stock_after_insert` - уменьшает остаток на складе после успешного добавления позиции в заказ

### 3. Хранимые процедуры
- `AddOrder(cust_id, book_id, qty)` - комплексная процедура создания заказа:
  - Получает цену книги
  - Создаёт запись в `Orders`
  - Добавляет позицию в `OrderItems`
  - (в реальном проекте сюда же можно добавить транзакцию)
- `UpdateOrderStatus(ord_id, new_status)` - обновление статуса заказа

### 4. Пользовательская функция
- `GetAverageRating(book_id)`  возвращает среднюю оценку книги по отзывам (с обработкой NULL → 0)

### 5. Примеры типичных данных и сценариев
- Несколько книг, авторов, издательств, клиентов
- Заказы с несколькими статусами (pending, shipped)
- Отзывы с оценками 4–5
- Демонстрация работы триггеров на уменьшение стока

## Навыки, которые здесь можно увидеть

- Проектирование реляционных баз данных
- Нормализация и связи многие-ко-многим (через OrderItems)
- Написание и отладка триггеров
- Создание хранимых процедур и функций
- Работа с агрегатными функциями и обработка NULL
- Бизнес-логика на уровне СУБД (контроль остатков, статусов)
- Понимание ACID и порядка выполнения триггеров (BEFORE / AFTER)
